# Rant-to-Launch

## Overview

Rant-to-Launch is a tool for solo founders to quickly launch products. It transforms a raw product idea ("rant") into eight essential content artifacts in a single request, compressing the time between idea and launch. The project focuses on generating specific, high-quality launch content rather than generic AI output, aiming to empower founders to ship rapidly.

## User Preferences

- **Voice**: confident, specific, founder-coded. Match the founder's voice if the rant has one; otherwise be direct and concrete.
- **No corporate fluff** — kill words like "leverage", "synergize", "unlock value", "revolutionize".
- **No emojis anywhere** — not in copy, not in UI, not in the storyboard visuals. The system prompt enforces this and the UI source is emoji-free by convention.
- **No hedging** — no "perhaps", "might", "could potentially". The founder needs lines they can publish, not options to consider.
- **Specific over clever** — concrete benefit beats clever wordplay. If the copy could be the headline of any product, it is wrong.

## System Architecture

The application uses a React frontend and an Express backend, backed by a PostgreSQL database.

**UI/UX Decisions:**
- **Single-page focus:** Dedicated pages for rant input and results display.
- **Prominent input:** The rant textarea is the central element on the home page.
- **Managed loading experience:** "Distilling your chaos…" message during synchronous content generation.
- **Granular copy functionality:** Individual copy buttons for each generated artifact.
- **Tabbed results organization:** Outputs are categorized under "Landing Page," "Social Content," "Visuals & Carousel," and "Plan" tabs.
- **Distinct visual theme:** Features magenta + cyan accents, serif display fonts for headlines, and monospaced fonts for metadata to convey a strong brand identity.
- **Recent runs display:** Shows the last 5-8 runs as simple breadcrumbs.

**Technical Implementations:**
- **Frontend:** Built with React, Vite, wouter, TanStack Query, shadcn/ui, and Tailwind v4.
- **Backend:** Express server managing API requests.
- **Content Generation Contract:** `launch-schema.ts` defines `LaunchPackageZodSchema` for validation and `LaunchPackageJsonSchema` for strict structured outputs with OpenAI. `SYSTEM_PROMPT` guides content generation.
- **Runtime voice previews:** Storyboard voiceover lines can be previewed through `POST /api/audio/tts`, which returns a short MP3 generated by Replit-managed OpenAI `gpt-audio`.
- **API Contract:** Defined by `openapi.yaml`, with Orval generating React Query hooks and Zod schemas.
- **Data Model:** Comprises `projects`, `source_inputs`, `generation_runs`, `asset_cards`, and `share_links` tables. `asset_cards` store individual generated outputs as `jsonb`. Schema changes are managed through Drizzle migrations in `lib/db/migrations/`; run `pnpm --filter @workspace/db generate` to author a new migration and `pnpm --filter @workspace/db migrate` to apply.
- **Identity Management:** Utilizes browser-local storage for project ownership and recent activity (no user authentication in MVP).
- **Input Limit:** 50,000 characters for rant input.
- **Slugs:** 10-character hex slugs for URL identification.
- **Per-section regeneration:** Individual sections can be regenerated via `POST /api/projects/:slug/sections/:section`, using specific contracts for each kind.

**Feature Specifications (Eight Outputs):**
1.  **Launch angle:** 2–3 sentences.
2.  **X / Twitter thread:** 5–7 tweets, each ≤ 280 characters.
3.  **LinkedIn post:** ~1000–1500 characters.
4.  **Carousel outline:** 6–8 slides with headline and body.
5.  **Newsletter blurb:** 150–250 words.
6.  **Landing page copy:** Headline, subheadline, CTA, 3–4 features, social proof, and 4–6 FAQ entries (question + answer). The landing preview renders 5 visibly distinct blocks (hero, proof strip, features grid, dedicated CTA band, FAQ). FAQ is required on generate/regen and round-trips through edit/save (PATCH validator is lenient — faq optional for legacy cards predating the FAQ block, but enforces 4–6 + non-empty Q/A when present). FAQ flows into copy/markdown/PDF/share exports.
7.  **Storyboard cards:** 5–6 frames with hook, source moment, visual, on-screen text, voiceover, CTA, and generated image.
8.  **Posting schedule:** 7 launch-day slots (`Launch`, `+1 hour`, `+3 hours`, `+6 hours`, `Next morning`, `Next afternoon`, `Final voting-window reminder`) with platform and content.
Outputs are strictly validated with Zod, including a single retry on failure. Visuals are generated in parallel for carousel outlines and storyboard cards using `gpt-image-1`, with image URLs integrated into the content.

## External Dependencies

-   **Database:** Replit-managed PostgreSQL.
-   **AI Model:** OpenAI via Replit AI Integrations proxy, using `gpt-5.4` for text, `gpt-image-1` for visuals, and `gpt-audio` for voiceover previews.
-   **Object storage:** Replit App Storage (Google Cloud Storage) via `@google-cloud/storage`.
